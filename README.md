## העלאה ל-GitHub Pages
הקבצים כאן בנויים לכתובת `https://oriyalic10-stack.github.io` והם **פתוחים לאינדוקס** (גוגל, Bing ובינה מלאכותית).
1. ב-GitHub: **New repository**. השם צריך להיות בדיוק `oriyalic10-stack.github.io`, והמאגר **ציבורי** (Public). (אם מאגר בשם זה כבר קיים ויש בו משהו — עצרו ופנו אליי, ואבנה לכתובת אחרת.)
2. חלצו את ה-ZIP. במאגר: **Add file ← Upload files**, וגררו את **התוכן** של התיקייה (`index.html`, `en`, `ar`, `privacy`, `terms`, `fonts`, `icons`, `og` וכל הקבצים, כולל `.nojekyll`). אל תעלו את קובץ ה-ZIP עצמו. לחצו Commit.
3. **Settings ← Pages ← Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, Folder = `/ (root)`. שמרו.
4. אחרי דקה-שתיים האתר עולה ב-`https://oriyalic10-stack.github.io`. בדקו את שלוש השפות: `/`, `/en/`, `/ar/`.

## הגשה ל-Google ול-Bing (אחרי שהאתר עלה)
1. **Google Search Console** (search.google.com/search-console) ← Add property ← **URL prefix** ← הדביקו `https://oriyalic10-stack.github.io/`.
2. בשיטת האימות בחרו **HTML tag** (אימות דרך DNS לא אפשרי ב-github.io). תקבלו שורה כמו `<meta name="google-site-verification" content="...">`. **שלחו לי את הקוד** ואבנה מחדש עם `--google-verification=הקוד` (או: קובץ HTML שגוגל נותנת, מעלים אותו לשורש המאגר).
3. אחרי האימות: **Sitemaps** ← הוסיפו `sitemap.xml`. אפשר גם ב-URL Inspection לבקש אינדוקס לדף הבית.
4. **Bing Webmaster Tools** (bing.com/webmasters) ← **Import** מ-Google Search Console. הוא מייבא את האתר המאומת ואת ה-sitemap בלי אימות נוסף.
5. אינדוקס לוקח בדרך כלל ימים עד שבועות. אין דרך להאיץ מעבר לבקשה הזו.
הערה: הקובץ `robots.txt` יושב בשורש `oriyalic10-stack.github.io` וחל על כל הכתובת, כולל האתר האחר שלך (`/Lag-BaOmer-website/`): הוא חוסם שם סורקי **אימון** של בינה מלאכותית, ולא משפיע על גוגל או על עוזרי חיפוש.

## לפני העלאה — חובה
1. **החלפת הדומיין.** בכל הקבצים מופיע `https://example.com` כמקום שמור. יש להחליף בדומיין האמיתי
   (או להריץ מחדש: `node build-site.js https://הדומיין-שלכם`).
2. **מבנה התיקייה.** יש להעלות את **התוכן** של התיקייה (`index.html`, `en/`, `fonts/` ועוד) כמו שהוא, בלי לשנות שמות או להפריד קבצים.
3. **סביבת בדיקות?** בנו עם `--noindex` כדי לחסום אינדוקס עד לעלייה לאוויר:
   `node build-site.js https://staging.example.com --noindex`

## איך לבדוק במחשב לפני העלאה
1. **חלצו את כל ה-ZIP** (קליק ימני ← Extract All / "חילוץ הכול"). אל תפתחו את `index.html` מתוך חלון ה-ZIP — אז חסרים הקבצים שלידו (פונטים, אייקונים) והדף ייראה שבור.
2. פתחו את `index.html` מהתיקייה שחולצה (לחיצה כפולה). האתר עובד גם ככה, כולל המעבר לאנגלית.

## אחרי העלאה
1. Google Search Console → הוספת הנכס → שליחת `https://הדומיין/sitemap.xml`.
2. Bing Webmaster Tools → אותו דבר.
3. בדיקת תמונת שיתוף: Facebook Sharing Debugger, וגם שליחת הקישור לעצמכם בוואטסאפ.
4. בדיקת נתונים מובנים: https://search.google.com/test/rich-results
5. הפעלת HTTPS והפניה מ-`www` לדומיין הראשי (או להפך) — אחד מהם בלבד כקנוני.
6. הפעלת דחיסת gzip/brotli ו-cache ארוך (`Cache-Control: public, max-age=31536000, immutable`) לתיקיות `fonts/`, `icons/`, `og/`.

## נראות בבינה מלאכותית (AI)
ההגדרות שלמטה **פעילות בגרסה הזו**. אם רוצים לחסום הכל זמנית (גרסת בדיקה), בונים עם `--noindex`.
מה נעשה:
- **`robots.txt`** מבדיל בין שני סוגי סורקים. **סורקי חיפוש ותשובות** (OAI-SearchBot, ChatGPT-User, Claude-SearchBot, Claude-User, PerplexityBot, Google-Extended, Applebot, Bingbot) **מותרים**: הם מאפשרים לעוזרי בינה מלאכותית למצוא ולצטט את האתר. **סורקי אימון מודלים** (GPTBot, ClaudeBot, CCBot, Applebot-Extended, meta-externalagent ועוד) **חסומים כברירת מחדל**. כדי לאפשר גם אותם בונים עם `--allow-ai-training`. הערה: לפי גוגל, `Google-Extended` מכסה גם אימון וגם תשובות ב-Gemini, ולכן השארתי אותו מותר. הוא לא משפיע על חיפוש גוגל רגיל.
- **נתונים מובנים** על הארגון, על השירות (חינמי, ישראל, שלוש שפות) ועל שאלות נפוצות.
- **8 שאלות נפוצות** שכתובות כשאלות אמיתיות, כולל "מה זה אתר העזרה?", "מה שעות הפעילות?" ו"האם זה שירות חירום?". התשובות מופיעות ב-HTML הסטטי, בלי צורך ב-JavaScript.
- **`llms.txt`**: סיכום קצר לעוזרי בינה מלאכותית, עם הנחיה לא להציג את האתר כשירות חירום. חשוב לדעת: גוגל אמרה שהיא מתעלמת מהקובץ ואין הוכחה שמערכות אחרות משתמשות בו. זה זול ולא מזיק, אבל לא "פתרון קסם".

מה שלא בשליטתנו: אף אחד לא יכול להבטיח שעוזר בינה מלאכותית ימליץ על האתר. מה שמשפיע הכי הרבה הוא **אזכורים וקישורים מגורמים אמינים** (בתי ספר, יועצות, ארגוני נוער, אתרי מידע על קווי סיוע), הוספת האתר ל-Google Search Console **וגם** ל-Bing Webmaster Tools (חלק ממערכות התשובות נשענות על אינדקס חיפוש), ותוכן מעודכן. כמה שבועות אחרי העלייה כדאי לשאול עוזרי בינה מלאכותית שאלות כמו "לאן ילד בישראל יכול לפנות כדי שיקשיבו לו?", ולוודא שהאתר מוצג נכון, ולא כשירות חירום.

## בדיקת הערבית (חשוב)
הערבית נכתבה בסיוע בינה מלאכותית (ערבית ספרותית מודרנית) ולא נבדקה על ידי דובר ערבית שפת אם. **לפני עלייה לאוויר מומלץ מאוד שדובר/ת ערבית ידקדק את הטקסטים**, במיוחד:
- מדיניות הפרטיות ותנאי השימוש (`legal-content.js`, האובייקט `ar`);
- הטקסטים הרגשיים בצ'אט (התשובות לכל נושא);
- הפנייה בלשון זכר ("لست وحدك"): שווה לבחון אם רוצים ניסוח נייטרלי יותר;
- שם האתר בערבית ("موقع المساعدة") הוא תרגום של "אתר העזרה", ואפשר להחליף בשם מותג.
מחרוזות הממשק בערבית נמצאות במילון בקובץ המקור `index-redesign.html` (בתוך `i18n`, תחת `ar`).

## עריכת המסמכים המשפטיים
הטקסט של מדיניות הפרטיות ותנאי השימוש נמצא בקובץ `legal-content.js` (בתיקייה שמעל), בעברית ובאנגלית. **כל שינוי באתר שמשפיע על מידע אישי** (טופס פנייה, כלי סטטיסטיקה, הרשמה, עוגיות) **מחייב לעדכן קודם את הטקסט שם**, ואז לבנות מחדש. מומלץ מאוד להעביר את הטקסטים לעיון איש מקצוע לפני העלייה לאוויר.

## עריכה ובנייה מחדש
העיצוב והתוכן נערכים בקובץ המקור `index-redesign.html` (בתיקייה שמעל). אחרי כל שינוי:
```
npm i jsdom
node build-site.js https://הדומיין-שלכם
```
הסקריפט מייצר מחדש את שני הדפים, ה-sitemap וה-robots.
